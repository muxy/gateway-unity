THE SETUP

Before you start

You should be comfortable adding GameObjects, editing Inspector fields, and attaching C# scripts. Start in a small test scene before connecting your production gameplay.

  • A Unity project. Use Unity 2020.3 or newer and a desktop target for this walkthrough.
  • The Hypeline SDK. Install it using the Git URL below, or use a local SDK checkout.
  • A Twitch broadcaster account with permission to install and activate the Twitch extension on its channel.
  • A viewer account or separate browser session to test the audience experience.
What has been validated?

The redesigned menu has been checked in Unity 6, and the package has compiled in Unity 2022. Test authentication, viewer actions, reconnects, and the standalone player on each platform you intend to support. A successful package import or connected indicator does not prove the full viewer-action flow.

STEP 01

Install the SDK

  1. Open Package Manager. In Unity, open Window → Package Manager (in newer Editors, Window → Package Management → Package Manager).
  2. Add Hypeline. Open the + or Add menu, choose Add package from git URL, and enter https://github.com/jrslyce/gateway-unity.git#codex/hypeline-developer-readiness. Alternatively, choose Add package from disk and select the SDK checkout's package.json.
  3. Let Unity finish. Wait for package resolution and script compilation. Check the Console for errors before continuing.
  4. Import the walkthrough sample. Select Muxy Hypeline in Package Manager, open its Samples section, and click Import next to DemoMaterials. This copies the examples into Assets/Samples/Muxy Hypeline/<version>/DemoMaterials; the sample does not appear in Assets until imported. If you previously downloaded either sample script, preserve your changes and keep only one copy of each class. Reassign any affected scene components and event bindings if you replace a script.

HYPELINE PREFABS

Add the menu and interaction alerts

Use these prefabs to add a creator-facing Stream Interactivity button to a main menu and show viewer actions in the game. Both connect to the same manager and existing Hypeline service.

  1. Add the manager. Open Packages → Muxy Hypeline → Prefabs and drag MuxyHypelineManager into the scene Hierarchy. Reuse an existing manager if there is one; keep only one active. Select the manager in the scene Hierarchy. In Game ID, use the prefilled gamelink-testing for testing or enter your game's own ID before Play mode. Expand Game Metadata to configure your game name and actions. Package assets are read-only; edit the scene instance.
  2. Add the menu. Drag MuxyHypelineMenu into the main-menu scene. Select it and drag the scene's manager into its Hypeline Manager Inspector field. Enter a Game Description and adjust Menu Button Position and Menu Button Size to fit your menu. The Twitch indicator lights up when connected; TikTok remains dim while its integration is coming soon.
  3. Add the alert. Drag MuxyHypelineInteractionAlert into the scene where viewer actions should appear. Select it and assign the same scene manager to Hypeline Manager before Play mode. Adjust Position, Size, colors, Play Sounds, volume, or optional category sound clips in the Inspector.
  4. Prepare the UI. Keep exactly one EventSystem in the scene, with an input module compatible with the project's active input system. The Hypeline prefabs use Unity UI and do not require TextMesh Pro. You can place them under a screen-space Canvas; without a parent Canvas, each creates an overlay Canvas at runtime. The menu has editable UI children; alert cards are built during Play mode.
One manager, one EventSystem

Use the Hypeline menu for creator connections and assign it the scene's single manager. Keep exactly one active EventSystem with the appropriate input module. TikTok is coming soon; Twitch is the available connection.

Connect a Twitch channel

  1. In the broadcaster's Twitch Creator Dashboard, install and activate the existing Twitch extension. Open its Configure view and select Get New Code.
  2. Enter Play mode, select Stream Interactivity, enter the six-character code, and select Connect. Codes expire after five minutes; request a fresh code if needed.
  3. Wait for the fox and text to show Connected. Gray indicates disconnected, amber connecting or reconnecting, and red a connection or authentication issue. A connected status verifies the connection, not a viewer action.

Test an alert and handle the action

To preview the alert without Twitch, enter Play mode and select the scene's MuxyHypelineInteractionAlert in the Hierarchy. In its Inspector, use Test Alert to set a sample viewer, action, and Help, Hinder, or Neutral category, then click Test Alert. Repeat to check stacking; an active Audio Listener and unmuted audio are needed to hear sounds. This is a local visual and sound preview: it does not send a viewer event, apply a game effect, or complete a transaction.

  1. On the manager, register an action your game supports using the same ID as the viewer action. For the walkthrough, configure healthpack as Spawn Healthpack, with category Help, state Available, impact 1, and count 65535. The viewer-action walkthrough explains how to bind its gameplay callback.
  2. From a separate viewer session, trigger the configured action in the Twitch extension. The alert listens to the manager's OnAnyGameActionUsed event and displays the viewer and action. By default it also logs the receipt to the Unity Console. Use an active Audio Listener and unmuted game audio to hear sounds.
  3. Implement and bind a separate gameplay handler that performs the effect and accepts or refunds the transaction as appropriate. The alert only displays the receipt; it does not fulfill or acknowledge the action. You can call ShowAlert(viewerName, actionName) for a visual preview, but that does not send or test a Twitch interaction.

Alerts appear for six seconds and fade during the last second; newer alerts appear above older ones.

STEP 02

Set up your Hypeline scene

Use the Hypeline menu as the connection interface and one MuxyHypelineManager prefab as the SDK owner. Its component is named MuxyHypelineManager. You can add these prefabs to an existing game or a fresh test scene.

  1. Add the manager and menu. Drag MuxyHypelineManager and MuxyHypelineMenu into the scene and assign the manager to the menu's Hypeline Manager field before Play mode. On the manager, leave Game ID as gamelink-testing for this walkthrough, or enter your game's ID before starting Play mode.
  2. Prepare input. Keep exactly one active EventSystem with an input module compatible with your project. The Hypeline menu does not create an EventSystem.
  3. Set game metadata. Select the manager in the scene Hierarchy, expand Game Metadata in the Inspector, and set a game name and theme. A logo texture is optional for the first test. The prefab in the package is read-only; edit its scene instance.
  4. Add a Health game text. In the manager's Game Texts, create element 0 with Label = Health, Value = 50, and Icon = fa-solid:heart. The sample updates this entry.
  5. Add the action sample. In the Hierarchy, create an empty GameObject and name it HypelineActionDemo. With it selected, use Add Component to add Hypeline Action Demo, or drag the imported HypelineActionDemo.cs onto it. Drag the scene's MuxyHypelineManager instance into the component's Hypeline Manager field before Play mode. The file and component are named HypelineActionDemo; the GameObject name is a label you choose.
  6. Enable input for the optional sample. Its debug buttons use Unity's legacy IMGUI input. If your project uses only the new Input System, select Both in Player → Other Settings → Active Input Handling and restart the Editor if prompted. This is required by the sample controls, not by the Hypeline panel.

Removing DemoMaterials

When you are finished testing, remove the demo components and their UnityEvent bindings from your scenes, then delete the imported DemoMaterials folder under Assets/Samples/Muxy Hypeline/<version>. Keep any code you adapted for your game. The Hypeline package and its prefabs are separate and should remain installed.

HypelineActionDemo.csDownload
using MuxyHypeline;
using UnityEngine;

// Tutorial scene only: use the prefab manager as the sole SDK owner.
public class HypelineActionDemo : MonoBehaviour
{
    public MuxyHypelineManager HypelineManager;
    private MuxyHypelineMenu menu;
    private int health = 50;
    private string status = "Open Stream Interactivity and connect with your Twitch code.";

    private void OnEnable()
    {
        if (HypelineManager == null)
        {
            Debug.LogError("Assign Hypeline Manager before enabling the demo.");
            enabled = false;
            return;
        }
        HypelineManager.OnAuthentication.AddListener(OnAuthentication);
    }

    private void OnDisable()
    {
        if (HypelineManager != null)
            HypelineManager.OnAuthentication.RemoveListener(OnAuthentication);
    }

    private void OnAuthentication(AuthenticationResponse response)
    {
        status = response.HasError ? "Authentication failed. Request a fresh PIN."
                                  : "Authenticated. Try Spawn Healthpack in the extension.";
        if (!response.HasError) PublishHealth();
    }

    // Wire the action's Dynamic GameActionUsed event to this public method.
    public void OnHealthpack(GameActionUsed used)
    {
        if (used.ActionID != "healthpack") return;
        ApplyHealth();
        HypelineManager.AcceptGameAction(used, "Added up to 10 health.");
        status = "Viewer action received: healthpack.";
        Debug.Log("Hypeline viewer action received: healthpack.");
    }

    private void ApplyHealth()
    {
        health = Mathf.Min(100, health + 10);
        if (HypelineManager.IsAuthenticated()) PublishHealth();
    }

    private void PublishHealth()
    {
        // The guide creates Health as Game Texts element 0.
        GameText text = HypelineManager.GetGameTextAt(0);
        text.Value = health.ToString();
        HypelineManager.SetGameTextAt(text, 0);
    }

    public void StartDemoPoll()
    {
        if (!HypelineManager.IsAuthenticated()) return;
        PollConfiguration config = new PollConfiguration
        {
            Prompt = "Where should we go next?",
            Mode = PollMode.Order,
            DurationInSeconds = 30
        };
        config.Options.Add("Forest");
        config.Options.Add("Desert");
        config.Options.Add("Ice Cave");
        config.OnPollUpdate = update =>
        {
            // The manager does not forward this delegate automatically.
            HypelineManager.OnPollUpdate.Invoke(update);
            if (!update.IsFinal) return;
            status = update.Count > 0 && update.Winner >= 0 &&
                     update.Winner < config.Options.Count
                ? "Poll winner: " + config.Options[update.Winner]
                : "Poll ended without a usable winner.";
            Debug.Log(status);
        };
        HypelineManager.SetPollConfiguration(config);
        HypelineManager.StartPoll();
    }

    private bool ShouldShowControls()
    {
        if (menu == null) menu = FindObjectOfType<MuxyHypelineMenu>();
        return menu == null || !menu.IsPanelOpen;
    }

    private void OnGUI()
    {
        if (!ShouldShowControls()) return;
        GUILayout.BeginArea(new Rect(16, Screen.height - 206, 440, 190), GUI.skin.box);
        GUILayout.Label("Hypeline action test | Health: " + health);
        GUILayout.Label(status);
        if (GUILayout.Button("Local test: add 10 health")) ApplyHealth();
        GUI.enabled = HypelineManager != null && HypelineManager.IsAuthenticated();
        if (GUILayout.Button("Start 30-second viewer poll")) StartDemoPoll();
        GUI.enabled = true;
        GUILayout.EndArea();
    }
}

The manager owns the SDK, pumps its updates, and starts the production transport when the Hypeline menu submits a code or restores a saved session.

STEP 03

Connect a Twitch channel

The broadcaster connects their own channel through the Hypeline menu. Viewers do not enter the broadcaster's code.

  1. Enter Play mode and select Stream Interactivity.
  2. Select Open Twitch, then install and activate the Twitch extension on the broadcaster's channel.
  3. Select Open configuration. On the extension page, choose Configure and generate a six-character code. Both buttons open the extension page; Configure is selected in Twitch.
  4. Enter the fresh code in the Hypeline panel and choose Connect. Codes expire after five minutes.
  5. Wait for You are connected and the green fox on the game menu. The Console reports connection and authentication stages without printing the code. TikTok remains a coming-soon label.
If connection stalls

The logo fill and countdown show the 8-second wait, not measured connection progress. The panel shows a warning if no authentication response arrives during that time. A response may still arrive. To retry, select Try again to reset the connection, then get a fresh code. Inspect the Hypeline: Console messages for transport and authentication timings. Keep PINs, tokens, and credential-bearing logs out of screenshots and messages.

The manager can restore a saved session using a refresh token stored in PlayerPrefs, which is not encrypted. Test a fresh login, a returning login, and disconnect/reconnect on each target platform.

Prove the complete round trip

  1. Enter Play mode and check that the sample controls in the Game view show health at 50. They hide while the Hypeline connection panel is open; close the panel to see them. The viewer poll button stays disabled until authentication.
  2. Use Local test: add 10 health once. Health should become 60, even before you have a PIN. This verifies the demo's game logic only. Restart Play mode to reset health to 50.
  3. Authenticate with the broadcaster's fresh PIN, then open the channel's active Twitch extension in a viewer session. Confirm the demo title, Health text, and Spawn Healthpack action appear. Test under the channel conditions Twitch requires for that extension placement.
  4. Select Spawn Healthpack through the extension. Follow its available test/interaction flow. If a purchase is involved, review the Twitch confirmation and cost; this guide does not assume a free-purchase simulator.
  5. Confirm Unity shows Health: 60, the demo status says Viewer action received: healthpack., and the extension's Health value becomes 60.

Test while the extension is visible to a viewer on the broadcaster's channel. A local button click alone does not verify a viewer action.

What the demo handler does
public void OnHealthpack(GameActionUsed used)
{
    if (used.ActionID != "healthpack") return;
    ApplyHealth();
    HypelineManager.AcceptGameAction(used, "Added up to 10 health.");
}

AcceptGameAction reports fulfillment. If your real game cannot perform an action, use RefundGameAction with the received event and a useful reason instead. Do not accept and refund the same transaction. Before shipping, deduplicate transaction IDs so repeated delivery cannot apply gameplay twice; the demo keeps the handler small and does not implement durable transaction tracking.

✓

Checkpoint A viewer-triggered event changed the sample health counter and updated its Game Text. This does not change your game's health until you connect the handler to your own gameplay. A local button click or authentication alone does not pass this checkpoint.

STEP 05

Keep viewers up to date

Game Texts are labeled values in the extension. Use them for the current level, player health, difficulty, or loadout. The sample sends its own Health value after authentication and whenever the sample counter changes.

// Update the Health entry created at index 0 in the manager.
GameText healthText = HypelineManager.GetGameTextAt(0);
healthText.Value = "60";
HypelineManager.SetGameTextAt(healthText, 0);

// Add an entry, then submit the whole list.
HypelineManager.AddGameText(new GameText
{
    Label = "Level", Value = "Forest", Icon = "fa-solid:dungeon"
});
HypelineManager.SubmitGameTexts();
Browse Game Text and action icon names

Search the 2,977 icons included in the Hypeline extension. Copy a name into a Game Text or action's Icon field. Game Info icons require an extension build with icon support. Updating the Unity package alone does not update an extension already hosted on Twitch.

AddGameText() and ClearGameTexts() change the manager's local list; call SubmitGameTexts() to publish it, including an empty list to clear Game Info. The code-only SDK uses SetGameTexts(GameText[]) to publish the complete list. Send meaningful state changes instead of resending identical data every frame.

Enable actions only when they can run

// Prefab manager: call when pausing / resuming valid gameplay.
HypelineManager.SetAllGameActionStates(GameActionState.Unavailable);
HypelineManager.SetAllGameActionStates(GameActionState.Available);

// After editing a manager action, explicitly submit the list.
GameAction action = HypelineManager.GetGameActionAt(0);
action.State = GameActionState.Hidden;
HypelineManager.SetGameActionAt(action, 0);
HypelineManager.SubmitGameActions();

After removing actions, call SubmitGameActions() to publish the updated list. Submitting an empty list sends a request to clear the available actions.

Use Unavailable for a visible action viewers cannot currently use and Hidden when it should not appear. Keep IDs unique. Choose finite counts for disruptive mechanics and restore availability only after the next scene or match is ready.

Add a game logo

Import a readable texture in a supported format: RGB24, RGBA32, or ARGB32. Enable Read/Write and choose a compatible texture format in its import settings. Use the SDK's static conversion helper:

GameMetadata metadata = HypelineManager.GetGameMetadata();
metadata.Logo = SDK.ConvertTextureToBase64(yourReadableTexture);
HypelineManager.SetGameMetadata(metadata);

Here yourReadableTexture is your own assigned Texture2D. Retain the existing metadata when changing the logo.

STEP 06

Let viewers choose what happens next

The demo's Start 30-second viewer poll button publishes a poll with Forest, Desert, and Ice Cave options. It uses PollMode.Order for one vote per viewer; PollMode.Chaos allows repeated voting. A duration of 0 is infinite, so use a positive duration for this test.

  1. While authenticated, select the demo's poll button once.
  2. In the viewer extension, select a poll option and submit a vote.
  3. After 30 seconds, verify the demo reports the winning option. With zero votes, it reports no usable winner.
  4. Apply a gameplay decision only on a final update, and validate the result before indexing an options list. Decide how your game should handle ties and no votes; the demo uses the reported winner when valid.

Optional: show the bundled polling UI

Outside Play mode, add MuxyHypelinePolling.prefab and assign its Hypeline Manager. Adjust its position and winner display duration in the Inspector.

To preview without connecting, enter Play mode, select the polling instance in the Hierarchy, and click Start Test Poll. A favorite-color poll appears and receives simulated votes automatically. Use Add Sample Vote or Finish Test Poll to control it. This preview stays local and does not start a live poll or send votes.

For a live poll, the demo's callback contains this bridge:

config.OnPollUpdate = update =>
{
    HypelineManager.OnPollUpdate.Invoke(update);
    if (!update.IsFinal) return;
    // Validate vote count and winner before applying game logic.
};

MuxyHypelineManager.StartPoll() passes its configuration to the SDK; it does not automatically forward PollConfiguration.OnPollUpdate into the manager's UnityEvent. The widget listens to that UnityEvent, so the bridge is required.

The widget shows vote counts, percentages, and the final winner when the callback provides one. The live display does not show a countdown; use the final callback to decide when the poll has ended.

using MuxyHypeline;
using UnityEngine;

// Alternative to the prefab manager. Do not run both integrations together.
public class HypelineCodeDemo : MonoBehaviour
{
    [SerializeField] private string gameID = "gamelink-testing";
    private SDK sdk;
    private string pin = "";
    private string status = "Request a code from the Twitch extension configuration.";
    private int health = 50;
    private bool authenticationPending;

    private void OnEnable()
    {
        sdk = new SDK(gameID);
        sdk.RunInProduction();
    }

    private void Update()
    {
        if (sdk != null) sdk.Update();
    }

    public void Authenticate(string enteredPIN)
    {
        if (sdk == null || authenticationPending || sdk.IsAuthenticated) return;
        enteredPIN = enteredPIN.Trim();
        if (enteredPIN.Length != 6)
        {
            status = "Enter the six-character PIN from the extension.";
            return;
        }
        authenticationPending = true;
        status = "Authenticating...";
        sdk.AuthenticateWithPIN(enteredPIN, response =>
        {
            authenticationPending = false;
            pin = "";
            if (response.HasError)
            {
                status = "Authentication failed. Request a fresh PIN and retry.";
                return;
            }
            PublishSetup();
            status = "Authenticated. Try Spawn Healthpack in the extension.";
        });
    }

    private void PublishSetup()
    {
        sdk.SetGameMetadata(new GameMetadata
        {
            Name = "Hypeline Unity Demo", Logo = "", Theme = "default"
        });
        GameAction action = new GameAction
        {
            ID = "healthpack",
            Name = "Spawn Healthpack",
            Description = "Add up to 10 health to the player.",
            Icon = "fa-solid:heart",
            Category = GameActionCategory.Help,
            State = GameActionState.Available,
            Impact = 1,
            Count = GameAction.InfiniteCount,
            OnGameActionUsed = new MuxyHypelineGameActionUsedEvent()
        };
        action.OnGameActionUsed.AddListener(OnHealthpack);
        sdk.SetGameActions(new[] { action });
        // Register the global callback too: it enables native action delivery
        // and dispatch to the per-action UnityEvent in this SDK revision.
        sdk.OnGameActionUsed(used =>
            Debug.Log("Hypeline action callback received."));
        PublishHealth();
    }

    private void OnHealthpack(GameActionUsed used)
    {
        health = Mathf.Min(100, health + 10);
        PublishHealth();
        sdk.AcceptGameAction(used, "Added up to 10 health.");
        status = "Viewer action received: healthpack.";
    }

    private void PublishHealth()
    {
        sdk.SetGameTexts(new[]
        {
            new GameText { Label = "Health", Value = health.ToString(),
                           Icon = "fa-solid:heart" }
        });
    }

    public void StartDemoPoll()
    {
        if (sdk == null || !sdk.IsAuthenticated) return;
        PollConfiguration config = new PollConfiguration
        {
            Prompt = "Where should we go next?", Mode = PollMode.Order,
            DurationInSeconds = 30
        };
        config.Options.Add("Forest");
        config.Options.Add("Desert");
        config.Options.Add("Ice Cave");
        config.OnPollUpdate = update =>
        {
            if (!update.IsFinal) return;
            status = update.Count > 0 && update.Winner >= 0 &&
                     update.Winner < config.Options.Count
                ? "Poll winner: " + config.Options[update.Winner]
                : "Poll ended without a usable winner.";
        };
        sdk.StartPoll(config);
    }

    private void OnGUI()
    {
        GUILayout.BeginArea(new Rect(16, 16, 440, 230), GUI.skin.box);
        GUILayout.Label("Hypeline code demo | Health: " + health);
        GUILayout.Label(status);
        if (sdk != null && !sdk.IsAuthenticated)
        {
            pin = GUILayout.TextField(pin, 6);
            GUI.enabled = !authenticationPending;
            if (GUILayout.Button("Authenticate")) Authenticate(pin);
        }
        GUI.enabled = sdk != null && sdk.IsAuthenticated;
        if (GUILayout.Button("Start 30-second viewer poll")) StartDemoPoll();
        GUI.enabled = true;
        GUILayout.EndArea();
    }

    private void OnDisable()
    {
        if (sdk != null) sdk.StopWebsocketTransport();
        sdk = null;
        authenticationPending = false;
        pin = "";
    }
}

For action callbacks: initialize each action's OnGameActionUsed UnityEvent before submitting it. Also register the SDK's global OnGameActionUsed delegate; native action delivery dispatches per-action events from inside that callback. Avoid applying the same gameplay effect in both callbacks.

Add returning-streamer authentication

The code demo intentionally asks for a fresh PIN on each enable. For a persistent login, load your platform's stored refresh token and pass it to AuthenticateWithRefreshToken. In either authentication callback, save the latest response.RefreshToken after success. Tokens can change on use. On failure, clear the unusable saved token and offer the PIN flow.

Keep tokens and PINs out of logs, source control, analytics, and screenshots. sdk.IsAuthenticated is a property; the manager component exposes HypelineManager.IsAuthenticated() as a method.

Lifecycle limits to account for

RunInProduction() and StopWebsocketTransport() return void; they do not provide an awaitable completion result. Test network loss, scene changes, logout, shutdown, and subsequent login in your target player.

VERIFY YOUR INTEGRATION

Test beyond a successful login

Use the following checks in order. Keep the Console visible, and test the Editor and standalone player on each platform you intend to support.

Checkboxes are a session checklist in this page, not automated test results. Refreshing resets them.

Build the test scene

Add your test scene to the enabled scenes in File → Build Settings, or the scene list of your active Build Profile in Unity 6. Select the desktop target, architecture, and backend you intend to ship. Build and run it, then repeat the live checks using a fresh or deliberately stored login.

Keep the SDK's native libraries enabled for the matching platform and architecture. This package includes an Editor linker callback that preserves reflection-loaded Mono TLS configuration types. Verify a stripped player as well as a development build; import/compilation success does not prove native loading, authenticated networking, or gameplay delivery.

WHEN SOMETHING DOESN'T CONNECT

Troubleshooting

Start with the first failed checkpoint. Fix compilation before authentication, and authentication before viewer actions.

Unity cannot find SDK types or UI assemblies

Confirm Muxy Hypeline is installed, its dependencies have resolved, and address the Console's first error. Add Muxy.Hypeline to any consumer .asmdef, and use using MuxyHypeline; for SDK types.

The manager's metadata fields are locked

The prefab inside Packages → Muxy Hypeline is read-only. Drag MuxyHypelineManager into the scene, select that instance in the Hierarchy, and expand Game Metadata in the Inspector. Edit and save the scene instance.

The Hypeline panel is unclickable

Keep exactly one active EventSystem with an input module compatible with the project. In a new-Input-System-only project, use Input System UI Input Module. Confirm the Canvas is enabled, no other UI blocks raycasts, and the Hypeline Manager reference is assigned before Play. The Hypeline prefabs do not require TextMesh Pro.

The sample's debug buttons cause input errors

The optional action and code-only samples use legacy OnGUI input. If the project uses only the new Input System, set Player → Other Settings → Active Input Handling to Both and restart the Editor if prompted. The Hypeline panel itself does not require these sample controls.

Twitch's Configure modal is empty

Confirm the extension is active under My Extensions, then reload the Twitch dashboard and reopen Configure. If it remains blank, contact Muxy or Twitch support. A code must come from the extension configuration.

PIN authentication fails or never finishes

Request a fresh code and check that the Twitch extension is installed and active. Inspect the Hypeline: Console status messages. If the panel shows no response after 8 seconds, a response may still arrive. Select Try again and request a new code to retry. Do not share PINs or tokens.

I am authenticated, but the viewer sees no game or actions

Confirm the extension is activated on the same channel. Reopen the viewer session under the conditions required by the extension's placement. Check that metadata and actions were published after authentication, action IDs are unique, state is Available, and count is usable. With the prefab route, set Inspector values before Play and submit runtime list edits explicitly.

The action appears, but nothing happens in Unity

Check healthpack spelling and the Dynamic GameActionUsed binding to HypelineActionDemo.OnHealthpack. In code, create the per-action UnityEvent and register the global SDK action callback. Keep SDK.Update() running. Check for exceptions in your handler. Do not use a local test button as evidence of a delivered viewer transaction.

A poll appears in the extension, but the Unity widget stays hidden

Assign the widget's manager and forward the configuration delegate to HypelineManager.OnPollUpdate.Invoke(update), as shown in the demo. Confirm you received poll updates. Use the callback's final state to judge completion.

It works in the Editor but fails in a player

Check the player log's first failure. For DllNotFoundException, verify the native library exists and its plugin import settings match the target. For EntryPointNotFoundException, check that managed code and native binaries came from the same SDK package. Compare architecture, backend, and stripping level. Retain the package's Editor linker callback. A TLS configuration initialization error and an actual network/certificate negotiation error require separate diagnosis.

Callbacks duplicate, re-login breaks, or shutdown hangs

Use one manager or code integration, not both, and remove listeners when custom components are disabled. The Hypeline menu resets the transport when you disconnect or choose Try again. Use a fresh code when reconnecting. Test disconnect, scene reload, network loss, and shutdown in your target player before release.

THE NEXT MILESTONE

Prepare for release

  • Confirm the Twitch extension is active and test authentication with the broadcaster's channel.
  • Test the Hypeline connection, failure, logout, and recovery experience. Review refresh-token storage and replace the prefab's PlayerPrefs approach where appropriate.
  • Gate actions during menus, loading, pause, and unavailable gameplay. Make fulfillment idempotent by transaction ID and handle failures with a refund path.
  • Define poll timeout, no-vote, and tie behavior. Validate optional widgets before relying on them.
  • Complete the live test checklist in the player for every platform/backend you support. Include reconnect and repeated-session tests.

For support, use support+unity@muxy.io from the package manifest or open an SDK issue. Include reproduction steps and redacted errors. Never attach PINs, JWTs, refresh tokens, or unredacted account information.
